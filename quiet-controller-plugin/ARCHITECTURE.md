# 구현과 권한

```text
Frieren OS Controller GUI / MCP / CLI (로그인 사용자)
    └─ Unix socket (설치 때 지정한 UID만 허용)
          └─ systemd 서비스 (root, 고정된 다섯 가지 요청)
                ├─ power-profiles-daemon D-Bus → 전력 프로필 / EPP
                ├─ intel_pstate sysfs → 터보 / 최소·최대 상한
                ├─ package RAPL sysfs → 지속·순간 전력 한도
                └─ coretemp sysfs → 온도 읽기

psutil → UI / CLI의 CPU·앱별 부하 측정
KWin D-Bus → 사용자 요청 시에만 효과 변경
systemd --user scope → 사용자 권한으로 새 작업에 CPUQuota 적용
```

## 제어 경계

- root 서비스는 네트워크 서버를 열지 않습니다. `AF_UNIX`만 허용됩니다.
- `/run/freiren-quiet/control.sock`는 `0660`, root와 대상 사용자의 기본 그룹 소유입니다. 추가로 `SO_PEERCRED`를 검사해 설치 시 지정한 UID 또는 root만 요청을 처리합니다.
- `status`, `mode`, `target`, `configure`, `reset`만 허용합니다. configure는 다섯 필드의 고정 구조로 CPU/EPP/RAPL 값의 형식·범위·관계를 검증하며 원래 전력 한도를 넘지 못합니다. 임의 경로, 셸 명령, PID, 파일 내용은 받지 않습니다.
- CPU 상한·터보 설정은 코드에 정의된 모드와 검증된 사용자 지정 값과 온도 규칙으로만 결정합니다.
- 서비스 코드는 root 소유이며 Python `-I`로 실행합니다. 사용자 Python 경로·환경변수에서 코드를 가져오지 않습니다.
- 서비스 파일시스템은 기본 읽기 전용이고, 필요한 CPU와 고정 RAPL 패키지 sysfs·런타임·상태 디렉터리만 쓰기 가능합니다. 커널 모듈, 사용자 홈, 실제 장치 파일에는 접근하지 않습니다.
- 서비스 CPUQuota는 한 코어의 10%, 메모리 상한은 120MiB입니다. 정기 센서 측정은 5초 간격이며 UI는 닫을 수 있습니다.
- GPIO, EC 레지스터, 팬 PWM, NVIDIA 전원 상태는 쓰지 않습니다. GPU 절전 상태를 읽는 데 GPU를 깨울 필요가 없습니다.

## 복원과 실패

`baseline.json`은 첫 설치 때 PPD 시작 전 캡처합니다. CPU 최소/최대 상한, 터보 상태, 각 정책의 EPP, 기존 전력 프로필, 모델을 기록합니다. 시리얼 번호와 사용자 토큰은 기록하지 않습니다. 실제 파일은 root만 읽을 수 있는 상태 디렉터리에 보관하며 Git에 포함하지 않습니다.

각 CPU 제어 작업은 변경 전 상태를 캡처하고, 읽어 확인합니다. 중간 실패 시 그 작업 전의 값으로 되돌립니다. 모드 전환도 실패 시 이전 설정으로 복원합니다. 실패나 미확인 센서 값을 정상값으로 표시하지 않습니다.

`restore`는 기본 출고 설정을 추정하지 않고 캡처한 상태로 돌아갑니다. PPD가 없던 첫 설치라면 PPD를 balanced로 돌린 후 원래 EPP를 복원합니다. 이후 AC/배터리 변경 등은 PPD가 다시 정책에 따라 처리할 수 있습니다.

KDE 또는 다른 도구의 전력 프로필 변경이 감지되면 원래 CPU 상한과 전력 한도를 복원하고 외부에서 선택한 전력 프로필을 유지합니다. 동시 실행 중인 TLP·auto-cpufreq 등 다른 CPU 제한 도구는 이 프로젝트의 지원 범위 밖입니다.

온도 임계값은 이 노트북을 위한 보수적 초기 조절값이지 팬 곡선이나 실험으로 확정한 최적값이 아닙니다. 목표에 도달하지 못하면 앱 부하·통풍·냉각 상태를 별도로 살펴야 합니다.

## 0.3 복원 지점

원래 baseline.json은 수정하지 않습니다. 첫 업데이트 때 package-0의 long_term/short_term 값을 power-baseline.json에 별도 기록합니다. 기기 식별 정보를 검증하고 재시작·업데이트 때 다시 캡처하지 않습니다. reset은 CPU/EPP/전력 한도를 복원하고 저장한 사용자 지정 값·목표를 초기화합니다. 서비스 종료와 제거도 전력 한도를 복원합니다. 전력 쓰기 실패 시 두 한도를 되돌리고 전체 프로필 전환도 직전 상태로 롤백합니다.
